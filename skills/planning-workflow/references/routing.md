# Routing examples

Use these cases when changing routing, not as required task context. The
requested outcome and actual authority decide the path; task nouns do not.

- "Fix this reproduced validation bug; expected behavior and test are attached."
  Implement and verify directly. No required coordinator, diagnosis, or plan.
- "Find out why this request intermittently fails."
  Diagnose read-only. Do not implement unless the original request allows it.
- "Interview me about this feature."
  Interview; finish with the requested brief. Do not implement.
- "Correct this guide using the attached facts."
  Edit directly. Writing a document is not an interview trigger.
- "Use reasonable defaults and finish the change."
  State material assumptions and continue without another confirmation.
- "Plan this migration, including cutover and rollback."
  Inspect relevant contracts, then plan. Do not implement a plan-only request.
- "Use architect to compare these proposed ownership boundaries."
  Return an inline design memo. Do not auto-activate architect for other tasks.
- "Challenge this proposed architecture."
  Review the design; do not confuse it with plan or diff review.
- "Explain what this PR changes."
  Explain; do not fix or present the explanation as merge approval.
- "Review this branch, but do not edit it."
  Return reviewer findings; do not enter an automatic remediation loop.
- "Implement this accepted change and resolve the required reviews."
  Implement, verify, run authorized review, and resolve in-scope blockers within
  its budget. Naming the next workflow is not completion.
- A required child skill is absent in a clean installation.
  Report that dependency, not a fictional invocation. Continue independent work
  or ordinary task execution only when the specialist was optional.

Review ready work without creating extra artifacts or asking questions that
repository evidence answers. Use an existing stable proof seam and preserve
actual permission boundaries. A delegated operation returns to its caller at
its assigned boundary even when the overall workflow has further work.
